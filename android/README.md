# 一方志安卓端（开发中）

目标是让商家**只用一台手机**开播：抖音 App 在前台直播，一方志在后台读弹幕、让 AI 用声音回答。
能在一台手机上跑通，放到第二台手机上在前台用自然也行。

**现在还不是能给商家用的软件。** 只有调试包，连的是开发用的控制台，在一台手机（荣耀 X50）上试过。里面有两部分：

- **直播工作台**（打开软件看到的）：一整屏的一方志直播页，和桌面端里显示的是同一个网页。页面通过一座和桌面端一样的桥
  （`window.yifangzhiDesktop`）让软件去读直播间弹幕，所以页面不用区分自己开在电脑软件还是手机软件里。
- **设置与验证**（左下角“设置”）：授权、运行记录，以及最初用来回答三个问题的验证界面：后台能不能读弹幕、
  系统会不会把它关掉、后台放的声音直播间里听不听得到。换一台新手机时先用它测一遍。

## 整条链路走通过一次

2026-10-09，荣耀 X50（安卓 15），调试包连本机的开发后端，没有悬浮窗权限，已关电池优化：

- 抖音在前台直播，一方志在后台。开播后一分钟内识别到“已开播”。
- 读到 2 条弹幕：1 条按规则判为不用回，1 条交给了 AI；AI 生成了回复，合成语音，在后台播了出来（页面上显示“互动回复 已播”）。
- 自动讲解在后台一直在生成、在播；下播也识别到了。
- 另外单独测过：切到桌面两分半钟，讲解没有断；连过一次的直播间会记在设备上，下次不用再粘贴。

**没有验证的**：AI 的回复在直播间里听起来怎么样（只确认过验证界面放的录音听得清）；连线上的控制台；播一小时以上；别的品牌的手机；
不关电池优化时的表现。**还没做的**：扫码登录（现在要在软件里输手机号和验证码）、授权引导、正式签名的安装包、新版本提醒。
已知的小问题：网页不在界面上时确认框弹不出来，所以“结束本场”要回到软件里点；顶栏在手机上偏挤。

## 它怎么读弹幕

和桌面端一样：在一张不显示的网页里打开商家自己的直播间（`live.douyin.com/<直播间号>`），连接和签名都由抖音自己的
网页完成，软件只把网页收到的弹幕抄一份。网页不登录任何抖音账号，只取弹幕文字、弹幕 ID 和“是否在播”，
不读观众的昵称和账号。这不是抖音官方接口，抖音网页改版时可能失效。

和桌面端不同的是“抄”的办法。桌面端旁听网络；安卓的系统浏览器内核没有那种办法，改成在网页自己的脚本运行之前
放进一小段脚本（`app/src/main/assets/collector-hook.js`），由它把弹幕连接收到的每一帧交给软件。

后台那张网页不下载直播的视频、图片和字体（`Browsing.refuses`）。不拦的话它每小时要下几个 G。

## 读弹幕、后台运行、后台出声：逐项验证的记录

在电脑上验证过（2026-10-09，用桌面端的 Electron 模拟“只能在网页里放脚本”这个条件，对着正在播的公开直播间，只数条数）：

- `collector-hook.js` 这个文件本身读到的帧和弹幕，与桌面端旁听网络读到的一条不差（三次：149 帧 85 条、106 帧 35 条、134 帧 21 条，漏 0 条）。
- 弹幕连接是网页自己建的，不在网页的后台线程里，所以网页里的脚本够得着。
- 直播间是否在播，脚本也读得到。
- 拦掉视频、图片、字体后弹幕照收：不拦时 50 秒下了 66 MB，拦掉后 60 秒 9 MB，其中大部分是打开网页时一次性下载的脚本。

在一台真手机上跑过一次（2026-10-09，荣耀 X50，安卓 15，系统浏览器内核 130，软件开在前台，对着一个没在播的直播间跑了一分半钟）：

- 抖音给的是带弹幕的电脑版网页，没有跳去“打开 App”，也没有要求验证或登录。
- 脚本确实赶在网页自己的脚本之前放进去了，网页建立了接收弹幕的连接，每 10 秒收到一次心跳并且都读得懂。
- 读到了“直播间未开播”。
- 测试声音放得出来；开始、停止正常，没有闪退。

同一台手机上，抖音在前台直播、验证版在后台，跑了一场（同日，10 分 44 秒，悬浮窗方式，已关闭电池优化，没放测试声音）：

- 每分钟一行的“仍在运行”一行不缺，进程没有被系统冻结或关掉。
- 弹幕连接一直连着：654 帧里 63 次心跳，相邻两帧最长隔 18 秒，没有读不懂的帧。
- 开播 30 秒内发现“已开播”，读到 8 条弹幕，没有重复。发出去的是不是正好这 8 条，要由发弹幕的人核对。
- 两次运行（1.5 分钟 + 10.7 分钟）一共收了约 28 MB、发了约 6 MB，其中大部分是每次打开网页时一次性下载的脚本。

同一台手机上又跑了两场短的（同日）：

- **声音**（3 分 25 秒，悬浮窗方式，每 20 秒放一次测试声音，媒体音量 6/16）：验证版在后台放声音没有被系统拦，和抖音同时出声；用另一台设备进直播间，**听得到**这段测试声音。没有用内录头。清不清楚、比主播说话小多少，还没有记录。系统里看到抖音直播用的是普通的麦克风收音方式（MIC），不是通话那种会消掉自己喇叭声音的方式，这和“听得到”对得上。
- **纯后台**（1 分 30 秒，不用悬浮窗）：识别了开播，读到 2 条弹幕，心跳正常。时间太短，只能说明“一开始是通的”。

**还没有验证的：**

- 不用悬浮窗（纯后台方式）能不能撑得住。只跑过一分半钟；系统浏览器内核对看不见的网页要过几分钟才开始放慢它。
- 播得更久（一小时以上）、手机发烫或内存紧张时会不会被关掉。十分钟那一场结束时电池温度 44℃。
- 声音的质量：直播间里听到的清不清楚、够不够响，要不要内录头。测试声音是录好的一句话，不是真正的 AI 讲解。
- 不关电池优化时会怎样。上面几场都关了。同一台手机外放再被自己的麦克风收进去，很可能被回声消除压掉，大概率要靠内录头。
- 别的品牌、别的系统版本的手机。

## 构建

需要 JDK 17 或更新的版本，以及安卓 SDK（`platforms;android-35`、`build-tools;34.0.0`、`platform-tools`）。

```bash
cd android
export JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home   # 这台机器上 JDK 的位置
export ANDROID_HOME="$HOME/Library/Android/sdk"

./gradlew :app:testDebugUnitTest    # 单元测试：解码、直播间号、拦截规则
./gradlew :app:assembleDebug        # 出 app/build/outputs/apk/debug/app-debug.apk
```

依赖先从阿里云的镜像取，镜像没有的再回到原站（`settings.gradle`）。打出来的是调试包，用的是本机自动生成的调试签名，
只能用来测试，不能发给商家。

调试包连的是 `http://localhost:4173`，和桌面端开发时一样；正式包连 `https://yifangzhi.com`（`app/build.gradle` 里的 `CONSOLE_URL`）。
手机上的 localhost 要转到电脑上的开发服务器，所以电脑上照常启动前端和后端之后，还要连上手机（USB 调试或无线调试）执行一次：

```bash
adb reverse tcp:4173 tcp:4173
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

调试包里的网页可以从电脑上检查（Chrome 的 `chrome://inspect`），正式包不行。

还有一种**预览包**（`./gradlew :app:assemblePreview`，出 `app/build/outputs/apk/preview/app-preview.apk`）：和调试包一样用调试签名，
但连的是线上 `https://yifangzhi.com`，不需要 `adb reverse`。它的包名多一个 `.preview`，可以和调试包并排装在一台手机上，
桌面上叫“一方志预览版”。用来拿真实账号自己试，同样不能发给商家。

## 在一台新手机上先做验证

打开软件，点左下角“设置”进入验证界面（它不登录、不连我们的服务器）：

1. 把三项授权尽量都点成“已允许”。
2. 在抖音 App 里开播，在直播间点“分享 → 复制链接”，回到验证版粘贴进去，点“开始”。
3. 切回抖音继续直播至少 10 分钟。用另一台设备进直播间发几条弹幕，记下发了什么、几点发的；同时听一听直播间里有没有每 20 秒一次的测试声音。
4. 下播，回到验证界面点“复制结果”，把内容发给开发。

记录里每分钟有一行“仍在运行”。缺了哪一分钟，就是那一分钟软件没在运行。先不勾“悬浮窗方式”测一次，
读不到或者中途断了，再勾上测一次。

## 文件

| 文件 | 作用 |
|---|---|
| `app/src/main/assets/collector-hook.js` | 放进直播间网页的那段脚本：抄弹幕连接收到的帧和直播间状态 |
| `DanmakuCollector.java` | 打开直播间网页，接脚本交来的数据，判断是否在播 |
| `DouyinFrames.java` | 把二进制数据解成弹幕。和 `desktop/src/douyinFrames.js` 是同一套读法，测试用例一一对应 |
| `RoomLookup.java` | 把分享链接或直播间网址换成直播间号。和 `desktop/src/roomLookup.js` 是同一套规则 |
| `RoomStatus.java` | 读网页查到的直播间状态 |
| `Browsing.java` | 以什么身份打开网页、哪些东西不下载 |
| `app/src/main/assets/console-bridge.js` | 放进控制台页面的那段脚本：搭起和桌面端一样的桥 `window.yifangzhiDesktop` |
| `ConsoleActivity.java` | 软件的界面：一整屏的直播工作台 |
| `ConsoleWeb.java` | 显示控制台的那张网页，以及页面请软件做事的那座桥的软件这一头 |
| `LiveService.java` | 后台部分：两张网页都归它，界面不在时接着读弹幕、接着出声 |
| `Wire.java` | 读到的东西交给页面时的格式，和 `desktop/src/wire.js` 一样 |
| `ProbeService.java` | 验证界面的后台部分：读弹幕、放测试声音、每分钟记一笔 |
| `ProbeState.java` | 运行记录，同时写进文件，软件被关掉也不丢 |
| `MainActivity.java` | 设置与验证界面 |
