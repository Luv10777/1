## 按资金风险排列的待定规则

| 事项 | 已确认的当前行为 | 需要决定 | 建议方向 |
| --- | --- | --- | --- |
| 已向供应商提交后的取消、超时与中断 | 未交付烟火全释放，供应商可能仍收费；本地取消不等于供应商取消 | 哪个阶段允许免费取消，无法确认供应商成本时如何结算 | 提交前免费取消；提交后等待供应商结果或成本凭据，单独定义平台赔付与用户取消 |
| 图片定价 | 1K、2K、4K 每交付一张均为 3 烟火；规划调用未单列价格 | 是否按模型和分辨率区分，怎样覆盖规划、重试及失败成本 | 用实际账户账单核对最高画质成本，再决定价格及目标毛利；烟火名义售价不是套餐赠送后的实际收入 |
| 到期后充值 | 充值不会恢复会员，余额保留；本次已加强付款前提示 | 继续允许充值，还是要求先续订 | 如果保留充值，持续明示用途；若要求先续订，前后端统一限制 |
| 续订叠加与赠送余额 | 同套餐期限可不断延长，赠送烟火不自动过期 | 最大可续订期限、赠送余额有效期与旧价格锁定期限 | 先比较套餐赠送烟火的有效单价与直充单价，再设期限上限和赠送规则 |
| 现金退款及运营调账 | 微信商户后台人工退款不会自动回收烟火；当前没有退款或调账入口 | 可退范围、已消耗余额、赠送烟火、会员期限、审批及回单依据 | 先明确全额、部分和重复退款规则，再实现独立退款流水及可审计的运营入口 |
| 续订新版时的原权益 | 同标识的新版本支付后立即替换当前权益，原期限继续叠加；历史订单快照保留 | 新版权益立即生效，还是原期限结束后生效 | 如果保留原权益，需要按期限保存并切换权益；不能仅依赖订单快照宣称已支持 |
| 会员期内升级套餐 | 只能续订相同标识，到期后才能换其他套餐 | 是否允许升级，如何补差价、计算剩余天数及赠送烟火 | 先确定补差规则和降级规则，再开放升级订单 |
| 手机支付 | 仅接入微信 Native 二维码 | 是否支持微信内 JSAPI、外部浏览器 H5，以及桌面与手机跳转流程 | 根据实际使用场景选渠道，并完成各自商户权限与回调联调 |
| 直播等其他模块成本 | 当前各业务模块已要求有效会员；视频反推已按成功分析扣 1 烟火，直播话术、语音等未逐次扣烟火 | 哪些成本包在会员内，哪些另计，是否设使用额度 | 以话术、语音与分析实际成本确定套餐额度和单次规则 |
| 套餐发布复核 | 运营白名单可新增并直接上架；本次限制同标识只上架一个版本 | 是否要求另一名运营复核，以及价格变更通知方式 | 明确审核角色和发布记录，再做审批流程 |

## 发布前需要补充的真实依据

以下工作不能由当前自动测试替代，也没有在本次修复中假定为已完成。
只有取得对应商户及供应商的实际数据，才可填写商业配置并开放正式收款或售卖。

- 微信真实商户的 Native 下单、扫码、通知、主动查单、关单与到账联调；公钥轮换方案。
- 图片最高画质及规划模型的真实成本，视频各模型、分辨率和输入模式的账户实际生效费率。
- 视频所有已开放比例及 `auto` 的最大像素面积，不能仅使用相邻插件中的 16:9 尺寸。
- V49 前的同标识多版本上架检查；运营决定下架哪个版本，历史订单和账户快照不自动改写。
- 公共层 `TaskService` 的新增恢复 DTO 接口按后端 README 的协作约定由双方审查。

## 截图结论的更新

预占与消耗不是两次余额扣减；此前明细把两次负数并列，容易造成误解，本次已区分实际收支与预占转移。
套餐目录是全局目录，没有租户字段，不能直接套用租户 RLS；其写权限由平台运营白名单校验。
同一个 `code` 可对应多个历史套餐版本，唯一约束应限制同时上架的版本，而不是禁止历史版本同标识。

今天的原有提交已经增加业务模块会员门禁及视频反推计费，所以“直播不受会员限制”已不符合当前版本。
真实微信支付、商业费率及成本上界仍需外部核验；自动测试通过也不能据此认为实际售卖成本已得到验证。
