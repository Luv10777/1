# 第三阶段承接差距分析

> 更新时间：2026-08-25
> 分支：`feat/phase-3-growth-closed-loop`

## 审计结论

仓库当前是 Vue 3 + Vite 浏览器端单体。第二阶段已经有工作流、创作编译器、媒体 QA、视频和连接器的领域契约，但尚未形成可部署的 Core API、数据库、队列 Worker 或微信/支付服务端。第三阶段先以领域契约和可交互消费者预览承接，不复制第二套后端。

## 承接检查

| 能力 | 状态 | 证据/缺口 |
| --- | --- | --- |
| 租户、商家、门店稳定 ID | 部分满足 | 第二阶段 Mock 对象携带 `tenantId/merchantId/storeId`；尚无服务端权威来源 |
| 登录、RBAC、租户隔离 | 未满足 | 现有认证为浏览器 Mock，路由守卫不是后端授权 |
| Campaign、作品、发布记录 | 部分满足 | Campaign 与创作工作区存在；无持久化查询 API |
| AI 网关和第三方密钥隔离 | 部分满足 | Provider 仅为 Mock，暂无服务端密钥管理 |
| 工作流状态、幂等、重试、成本、审计 | Mock 满足 | `src/domain/orchestrator.js` 有浏览器契约；无可恢复持久化 Worker |
| 对象存储、消息队列、回调 | 未满足 | 当前为 Mock Object Storage；无 Redis/RabbitMQ/Webhook 服务端 |
| 数据库迁移和恢复方案 | 未满足 | 仓库没有迁移目录或数据库连接配置 |
| 消费者小程序 | 首个 Mock 增量 | 新增统一多商家上下文、商品、购物车、草稿订单/Handoff 契约 |
| 微信 AI Handoff | 未接通 | 账号权限、官方配置和真机环境未提供；当前仅本地一次性 Token 契约 |
| 微信支付 | 未接通 | 未做支付主体/服务商资质决策，禁止伪造支付成功 |

## 支付主体决策

在商家准入、微信支付主体和服务商/子商户资质未确认前，第三阶段只实现 `PaymentRoute` 领域接口和 Mock 状态机，不开放真实收款。首选决策顺序：

1. 若全部订单由单一直营主体收款，采用普通商户小程序支付。
2. 若平台为多个独立商家代收，评估服务商/平台商户与子商户模式，并按商户资质逐一开通。
3. 未完成准入的商家只能浏览、咨询、预约留资或导出订单草稿。

## 外部阻塞

- 微信 AI 开发模式、小微 Handoff 权限和真机测试账号未提供。
- 微信支付商户主体、`appid`、`mchid`/服务商字段、API v3 证书和回调域名未提供。
- 生产数据库、对象存储、消息队列、密钥管理和监控环境未提供。

这些事项不能通过前端 Mock 标记为“已完成”。
