# 商城企业支付宝收款

一方志官方店的实物订单提交成功后，显示企业支付宝收款码、后端计算的订单金额和订单号。
收款方为嘉兴市梧曜科技有限公司。二维码直接裁剪自经营者提供的原图，裁剪前后解码内容一致。

## 使用流程

顾客在商城点击“立即购买”，填写收货信息并提交订单后，在原窗口扫码付款。
同一手机可保存二维码，再通过支付宝扫一扫从相册识别；付款时输入订单金额并备注订单号。
订单查询链接可再次打开付款指引，并查看后续确认和物流进度。

商家在企业支付宝核对实际到账金额及订单号后，在订单管理中点击“核实收款并确认订单”。
确认、发货、完成或取消后的订单不再提供收款码。取消仅恢复库存；已收款项需要向实际收款方
申请并核实退款，不会自动原路退回。

## 配置与接口

后端通过 `growth.commerce.alipay` 配置付款指引，仅对指定门店的正金额待确认订单生效。
其他店铺不返回该企业收款码，保持与各自商家确认交易的流程。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `COMMERCE_ALIPAY_STORE_ID` | `5` | 一方志官方店；设为 `0` 可停用 |
| `COMMERCE_ALIPAY_RECIPIENT` | 嘉兴市梧曜科技有限公司 | 展示实际收款主体 |
| `COMMERCE_ALIPAY_QR_CODE_URL` | `/images/payments/company-alipay-qr.png` | 前端同源二维码资源 |

创建订单、查询订单和商家订单响应新增可空的 `payment` 字段，包含 `method`、`recipient`、
`qrCodeUrl`。当前方式为 `ALIPAY_MANUAL`，是否返回付款指引由服务端按门店、金额和订单状态判断，
订单金额继续由后端实时校验价格与库存后计算。本次不修改数据库结构。

本次接入的是企业支付宝收款码，需要人工核实到账。系统没有支付宝开放平台的交易回调、自动
查单或自动退款，不会因显示二维码或顾客点击按钮而把订单标为支付成功。

## 验证

前后端测试覆盖官方店收款范围、其他门店隔离、实际订单金额、待确认状态、已处理订单不重复
提示付款，以及订单提交失败时保留表单和成功后防止重复提交。构建与部署结果以实际运行记录为准。
