# 用户 UID 与服务商

2026-11-11 新增，2026-11-17 改成「团队账户 + 成员权限」（迁移 V84）。业务规则由业务方拍板，代码在 `backend/growth-api/.../partner/`、
前端 `partner/`（服务商后台，挂在一方志站的 `/partner/` 下）和 `src/views/PlatformPartnersView.vue`（管理后台「服务商」页）。

## UID

- 每个账号有一个 UID（`users.uid`）：8 位随机数字，注册时由数据库默认值 `next_user_uid()` 生成，永不重复。
  V79 给已有账号逐个补号。
- 用户在 wy 站「套餐与权益」页能看到自己的 UID，登录接口和 `/api/auth/me` 也返回 `uid`。
- 管理后台「用户管理」能按 UID 搜索。

## 服务商

服务商就是平台开通的合作公司。每家服务商有一个**团队账户**：开通时指定的负责人（老板）的一方志商户。
平台线下收款后发的烟火进团队账户；团队成员都是这个商户的员工，在一方志里创作直接扣它，分给名下商户也从它扣。
服务商不再单独记「可分配烟火」，V84 把原来的余额一次性转进了团队账户。

**没有 BD 了**（2026-11-17 业务方确认直接删除）：V84 把 BD 账号移出服务商，名下商户归整个服务商，不再分到个人。

| 谁 | 能做什么 |
|---|---|
| 平台（管理后台「服务商」页，限有服务商管理权限的运营） | 建服务商并按 UID 指定负责人（负责人的商户就是团队账户）；线下收款后把烟火发进团队账户；停用 / 启用；分页看名下商户和发放记录；按 UID 查商户归属并改归属或解除归属 |
| 负责人（`OWNER`，平台开通） | 全部权限；只有负责人能给成员「分配烟火」「财务查看」和设每月分配上限；可以把团队管理交给成员 |
| 成员（`MEMBER`，按手机号加入团队账户） | 按勾选的权限做事，见下面「团队与权限」 |

### 进入服务商后台

- 服务商后台在 **wy.yifangzhi.com/partner/**，和一方志是同一个域名、同一个登录（令牌存在同一处）。
- 一方志站右上角：当前账号是服务商成员（服务商启用中）时显示「服务商后台」按钮，在新标签页打开。只在网页上的 AI 创作站显示，
  主域名、桌面端和安卓端不显示。是否成员由 `GET /api/partner/membership` 判断，不是成员也正常返回。
- 没登录时打开服务商后台，会跳到一方志登录页，登录后回到原来那一页。
- 旧地址 partner.yifangzhi.com 上线后改成跳转到新地址，过一段时间再下线。

### 团队称呼与欢迎窗口

- 成员（包括负责人）第一次进服务商后台时，先弹「在团队里怎么称呼你？」：必须填（不能关掉），预先填好账号名，1 到 20 个字，
  同一家服务商内不能重名（`partner_members.display_name`）。之后在右上角点名字可以改；有团队管理权限的人也能在团队页帮别人改。
- 称呼只在服务商后台里用（激活码生成人、分配记录操作人、跟进记录、看板、商户「谁添加的」），不改一方志账号名。还没填的显示账号名。
- 填好称呼之后，每个账号每天第一次进工作台弹欢迎窗口：公司名（服务商名称）、「称呼，下午好」（0-6 点夜深了、6-11 早上好、
  11-13 中午好、13-18 下午好、之后晚上好）、今天待跟进的商户、名下商户、7 天内到期、团队烟火、本月生成激活码。

### 团队与权限

成员都是团队账户的员工。负责人或有「团队管理」权限的成员在「团队」页按手机号添加：

- 手机号没注册过：在团队账户里新建一个员工账号，以后用这个手机号登录一方志；
- 已经是团队账户的员工（例如在一方志「员工管理」里加过的店员）：直接加进服务商；
- 注册了别的商户的手机号：加不进来，要换一个号（一个手机号只能属于一个商户）。

权限逐项勾选（负责人永远是全部权限）：

| 权限 | 能做什么 | 新加成员默认 | 谁能给 |
|---|---|---|---|
| 商户 `tenants` | 看名下商户、按 UID 添加商户、直接续期、档案与跟进、工作台待办和经营看板 | 开 | 负责人，或有团队管理且自己也有的成员 |
| 激活码 `codes` | 生成、作废、导出激活码 | 开 | 同上 |
| 分配烟火 `distribute` | 从团队账户分烟火给名下商户，看自己分出去的记录；可设每月上限（`distribute_monthly_cap`，按北京时间自然月，空表示不限） | 关 | 只有负责人 |
| 财务查看 `finance` | 看平台发放记录、全部分配记录、看板里的烟火数字 | 关 | 只有负责人 |
| 团队管理 `team` | 添加、移除成员，改成员的权限和称呼 | 关 | 负责人，或自己有团队管理的成员 |

- 有团队管理权限的成员不能改自己的权限，不能动负责人；分配烟火、财务查看和每月上限只有负责人能改。
- 移除成员：移出服务商，同时把他从团队账户移除（账号停用、不能再登录和用团队烟火，手机号释放）。他生成的激活码照常可用，加过的商户仍在名下。
- 负责人只能由平台在管理后台添加和移除。平台加的账号如果已经是本服务商成员，会升为负责人。
- 团队列表所有成员都能看，手机号只给有团队管理权限的人。
- 成员在一方志里创作的消耗目前没有按人上限，只有「分给商户」受每月上限约束。

### 服务商后台的交互

列表只用来浏览和筛选；点一行打开右侧详情抽屉，修改都在抽屉里做；新增类操作（添加商户、添加成员、生成激活码、批量分配烟火）用居中弹窗。
每次提交前先在页内确认这次改动的结果（例如分配后双方余额、续期后的到期日、移除成员的后果），不用浏览器自带的确认框。
侧栏按权限显示入口（工作台、经营看板、名下商户、激活码、烟火、团队），没有权限的页面直接打开会回到工作台；真正的校验在后端。

- 名下商户：商户详情抽屉里有基本信息、使用情况、上手进度、往来记录、档案与跟进、会员续期、分配烟火（分配权限）；勾选多个商户后批量分配烟火（分配权限）。
- 团队：成员列表带权限、本月分配 / 上限、加的商户数和激活码统计；成员详情抽屉里看他做了什么、改权限和称呼、移出团队。
- 激活码：生成弹窗（生成后直接复制或导出）、激活码详情抽屉（作废），可按生成人筛选。
- 烟火：团队烟火（赠送 / 充值）、平台发放记录（财务权限）、分给商户的每一笔（财务权限看全部并可按操作人筛，只有分配权限的只看自己的），未到账的可以补上。
- 添加商户先按 UID 查询确认：姓名只显示第一个字，已归属其他服务商的只提示「已归属其他服务商」，不透露是哪家。

### 名称与余额

- 服务商的名称就是平台在管理后台「服务商」页设置的名字（可在详情里点「改名称」修改），服务商后台的左上角、面包屑、标签页标题、欢迎窗口都用它。
- 服务商后台右上角显示团队烟火（团队账户的可用烟火，和团队成员在 wy 站右上角看到的是同一个账户）。

### 工作台与经营看板

- **工作台**（登录后的首页）：有「商户」权限的成员看到今天要跟进的商户，按类分组，点一条打开商户详情：
  - 预约跟进（档案里约好的下次跟进，7 天内和已到时间的）；
  - 7 天内到期；30 天内刚过期；
  - 烟火余额不足：可用烟火不到**最近一笔充值的 10%**（例如上次充了 1000，余额到 100 提醒；充值含服务商分配和充值码，没充值过的不提醒）；
  - 开通了还没用过（有过会员但从没扣过烟火）；7 天没有使用（会员有效，最近一次使用在 7 天前）。

  右边是团队烟火、本月生成激活码和常用入口。
- **经营看板**（商户权限）：今天 / 7 天 / 30 天 / 90 天。商户（名下、新增、会员有效、7 天内到期、活跃、首次使用）、
  使用（商户消耗和次数、按功能的消耗、消耗最多的商户）、激活码（生成、兑换、直接续期、作废）、每天趋势、成员做的事（加的商户、生成和被兑换的激活码、直接续期）。
  有财务权限的另看平台发放、分给商户、团队烟火和每个成员分出的烟火。
- **商户详情**有「使用情况（近 30 天）」和「上手进度」（开通会员、建立门店、上传商品、完成第一次创作，系统按商户真实数据判断）。
- 服务商只看到商户的烟火数和使用次数，**不显示作品内容**。
- 这些数字要逐个商户在各自的租户里读账本，商户上百之后会变慢，届时改成每天汇总。

### 名下商户与归属

- 归属按**商户**算（同一商户的管理员和店员一起），以第一次为准，整个服务商共有：
  - 成员按 UID 添加（来源 `UID`，`partner_tenants.changed_by` 记是谁加的）；
  - 商户兑换了某家服务商生成的激活码，且当时还没有归属（来源 `CODE`）。
- 已经归属的商户，别家服务商不能再按 UID 添加；兑换别家的激活码照样开通会员，但不改归属。团队账户自己不能加成名下商户。
- 只有平台能改归属（来源 `PLATFORM`）或解除归属。

### 烟火

- 平台发放：烟火记入团队账户的**充值烟火**（团队账户账本 `PURCHASE`「平台发放服务商「名称」烟火：备注」），服务商流水记一条 `GRANT`
  （备注写收款流水号）。两边在团队账户的同一个事务里写，同一请求只发一次。
- 成员在一方志里创作：和普通店员一样直接扣团队账户。
- 分给名下商户（分配权限）：从团队账户扣，先扣赠送；对方收到时赠送仍是赠送、充值仍是充值。团队账户记一条 TRANSFER（转出），
  商户账本记「服务商「名称」分配烟火」。不按这笔记邀请返利。只能分给自己名下的商户，余额不足或超出自己的每月上限时拒绝。
- 一笔分配分三步：在团队账户的一个事务里锁服务商、核对上限、扣团队账户、记下分配（`partner_distributions`，状态 `PENDING`）；
  再切到商户入账；最后标记到账（`DONE`）。每一步都按 `requestKey` 去重，中途失败的一笔显示「未到账」，点「补上」用原来的请求再走一遍，不会重复扣。
- 批量分配：在名下商户列表里给几个商户各填烟火数，一次确认。合计超过团队烟火时页面先拦下；
  每个商户单独一笔请求、单独一个 `requestKey`，某一笔失败（例如超出每月上限）只标在那个商户下面，其余照常到账，再点「分配」只重试没成功的。
- 分配记录里 V84 以前的记录：来源 `POOL` 是从原来的可分配烟火分出的，收款方 `BD` 是以前分给 BD 的，只做展示；还没到账的 `POOL` 记录仍能补上。
- 烟火看板的「累计购买」把服务商分给商户的这部分单列为来源 `PARTNER`。

### 激活码

- **不限个数**（V84 删掉了 `partner_code_quotas`）：有激活码权限的成员可以生成全部激活码套餐（按套餐标识的**最新**版本，上没上架都行），
  每批最多 200 个，同一请求重复提交返回同一批码。
- 服务商生成的码记在 `billing_redeem_codes.partner_id`，生成人记在 `created_by`，和平台生成的激活码一样一码一用；兑换后按上面的规则决定归属。
- 作废：有激活码权限的成员能作废本服务商没兑换的码。已兑换的码不能作废。
- 导出：激活码页「导出表格」按当前筛选导出 CSV（Excel 直接打开）。
- 因为不限个数，有激活码权限的成员可以给任何人开会员，系统只能事后按生成人追查；这个权限要给信得过的人。

### 到期与直接续期

- 名下商户可按「7 天内到期 / 30 天内到期 / 已过期 / 从未开通」筛选，按到期时间从早到晚排。按到期筛选时要读全部名下商户的会员状态，商户很多时会慢一些。
- 直接续期（商户权限）：在商户详情里选套餐，直接给商户开通或顺延（还没到期的从原到期日往后加），不用商户输入激活码。
  实现上是生成一个备注为「直接续期」的码并立即替商户兑换，激活码列表里能看到，便于对账。同一请求重复提交不重复顺延。

## 数据

V79 新增 `partners`、`partner_members`、`partner_code_quotas`、`partner_tenants`、`partner_credit_ledger`，
并给 `billing_redeem_codes` 加 `partner_id`。这几张表和 `billing_redeem_codes`、`billing_plans` 一样是平台级数据，
**不开行级隔离**：服务层先核对平台运营或服务商成员身份和权限，服务商只能读写自己那一家。烟火都记在商户（含团队账户）自己的账本里，照旧受 RLS 约束。

V84：
- 删除 BD 成员，删掉 `partner_tenants.bd_user_id`；`partner_members.role` 只剩 `OWNER` / `MEMBER`。
- `partner_members` 加 `can_tenants`、`can_codes`、`can_distribute`、`can_finance`、`can_team`、`distribute_monthly_cap`、`display_name`（同一服务商内唯一）。
- `partners` 加 `team_tenant_id`（取最早的负责人所在商户），把 `credits_available` 余额转进团队账户（团队账本记一条 `PURCHASE`，服务商流水记一条 `TRANSFER`），
  然后删掉 `credits_available`；`partner_credit_ledger.available_after` 改为可空（之后的发放不再有「发放后余额」）。
  有可分配烟火却没有负责人的服务商会让迁移失败，要先补上负责人。
- 删掉 `partner_code_quotas`。

## 接口

服务商后台（登录账号必须是一家启用中的服务商的成员，否则 403；各项再按权限核对，没有权限也是 403）：

| 接口 | 权限 | 说明 |
|---|---|---|
| `GET /api/partner/membership` | 登录即可 | `{member, partnerName, role, active}`，一方志站决定显不显示入口；不是成员时 `member` 为 false |
| `GET /api/partner/me` | 成员 | 服务商（`creditsAvailable` 是团队烟火）、可生成的套餐 `plans`、名下商户数、`role`、`permissions`、`displayName`、`userName`、团队账户 `account`、本月生成激活码 `monthCodes` |
| `PUT /api/partner/me/name` | 成员 | `{displayName}` 设自己的团队称呼 |
| `GET /api/partner/workbench` | 商户 | 待办：`todos`（`type` 为 `EXPIRING`/`EXPIRED`/`LOW_BALANCE`/`NOT_STARTED`/`IDLE`，带商户）和各类数量 |
| `GET /api/partner/dashboard?days=` | 商户 | 经营看板，`days` 取 1、7、30、90；烟火数字只给财务权限 |
| `GET /api/partner/tenants` | 商户 | 名下商户（含会员状态、烟火余额、谁添加的），`keyword` 按商户名、联系人、UID 搜；`expiry` 取 `SOON7`/`SOON30`/`EXPIRED`/`NEVER` |
| `GET /api/partner/lookup?uid=` | 商户 | 按 UID 预查询：商户名、打码姓名、`tenantState`（`NONE`/`MINE`/`OTHER`） |
| `POST /api/partner/tenants` | 商户 | `{uid}` 按 UID 添加 |
| `GET /api/partner/tenants/{tenantId}` | 商户 | 商户详情：会员和余额、这家服务商分给他的烟火（分配或财务权限）、他兑换过的本服务商激活码（含直接续期） |
| `POST /api/partner/tenants/{tenantId}/renewals` | 商户 | `{requestKey, planCode}` 直接续期 |
| `GET/PUT/POST /api/partner/tenants/{tenantId}/crm`、`/profile`、`/follow-ups`，`GET /api/partner/follow-ups/due` | 商户 | 商户档案和跟进记录 |
| `POST /api/partner/tenants/{tenantId}/credits` | 分配 | `{requestKey, credits, note}` 从团队账户分给商户 |
| `GET /api/partner/distributions` | 分配或财务 | 分配记录；财务权限可按 `tenantId`、`actorUserId` 筛，只有分配权限的只返回自己的 |
| `POST /api/partner/distributions/{id}/retry` | 分配 | 补上未到账的一笔 |
| `GET /api/partner/ledger` | 财务 | 平台发放记录 |
| `GET /api/partner/team` | 成员 | 团队成员（权限、本月分配、加的商户数、激活码统计；手机号只给团队管理权限） |
| `POST /api/partner/team` | 团队管理 | `{phone, name, permissions, monthlyCap}` 按手机号加成员 |
| `PUT /api/partner/team/{userId}` | 团队管理 | `{permissions, monthlyCap, displayName}` 改成员 |
| `DELETE /api/partner/team/{userId}` | 团队管理 | 移出团队并停用他在团队账户的员工账号 |
| `GET/POST /api/partner/codes` | 激活码 | 查看 / 生成激活码，生成参数 `{requestKey, planCode, quantity, note}`；查看可传 `keyword`、`status`、`createdBy` |
| `POST /api/partner/codes/{id}/void` | 激活码 | 作废没兑换的激活码 |

平台（服务商管理权限）：`/api/platform/partners` 下的列表、新建、负责人账号增删、`PUT /{id}` 改名称和联系方式、启停、
`POST /{id}/credits` 发烟火（进团队账户）、名下商户、发放记录、`GET lookup?uid=` 查归属、`PUT assignments/{tenantId}` 改归属。

## 上线

1. 后端随 V84 发布。V84 会删除 BD、把可分配烟火转进团队账户；上线前确认每家有可分配烟火的服务商都有负责人。
2. 前端：`npm run build` 会同时构建一方志站（`dist/`）和服务商后台（`dist/partner/`），一起发布。
   站点的 nginx 要给 `/partner/` 单独的回退（`try_files $uri $uri/ /partner/index.html`，加 `X-Robots-Tag: noindex`），参照 `deploy/nginx.conf`；
   正式服的 nginx 不在仓库里，要照着改。
3. partner.yifangzhi.com 改成 301 跳转到 `https://wy.yifangzhi.com/partner/`，之后可以从 API 的 `growth.cors.allowed-origins` 里去掉它。
4. 在管理后台「会员套餐」建好月卡、季卡、年卡后，服务商才有套餐可以生成激活码。
5. 本地开发：`npm run dev` 和 `npm run dev:partner` 一起开，在 4173 打开 `/partner/`（一方志开发服务器把 `/partner` 转给 4178），这样两边是同一个登录。
