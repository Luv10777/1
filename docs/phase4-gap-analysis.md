# 第四阶段承接差距分析

> 更新时间：2026-08-25
> 分支：`feat/phase-4-saas-commercialization`

## M0 审计结论

仓库当前为 Vue 3 + Vite 浏览器端单体。前三阶段已提供商家工作台、内容工作流契约、消费者预览、交易/CRM/归因/增长领域 Mock，但没有 Core API、数据库迁移、队列 Worker、服务端 RBAC、支付适配器或真实小程序/支付权限。

## 承接检查

| 能力 | 状态 | 依据/缺口 |
| --- | --- | --- |
| 多租户、商家、门店稳定 ID | 部分满足 | 前端领域对象带租户字段；没有服务端权威会话和隔离测试 |
| AI 网关与供应商成本 | Mock 满足 | Provider 统一契约存在；无真实网关、价格快照和成本服务 |
| 工作流点数预占/结算 | Mock 满足 | Phase 2 Orchestrator 有浏览器内存账；无持久化账本和恢复 Worker |
| 消费者订单/支付/退款/核销 | 部分满足 | Phase 3 仅有本地订单草稿和交易状态契约，未接真实支付 |
| SaaS 账单与消费者账务隔离 | 本次冻结边界 | 新增 `billing.js` 使用独立 `saas_order`、订阅、信用账本命名；尚无数据库约束 |
| 数据库迁移/备份/恢复 | 未满足 | 仓库没有迁移目录、数据库连接或恢复演练记录 |
| 服务端租户/RBAC/职责分离 | 未满足 | 当前认证和路由守卫为浏览器 Mock |
| 商家入驻、合同、发票、Provisioning | 未满足 | 尚无 API、审核队列或真实开票/电子签适配器 |
| 销售 CRM、实施、客服、CSM | 未满足 | 当前只有工作台占位路由和文档契约 |
| FinOps、毛利、预算和供应商健康 | 首个领域骨架 | 本次先落地套餐、用量、点数和成本承接契约，仍为内存 Mock |

## 四种能力状态

- **仅 Mock**：套餐目录、订阅、权益计算、用量事件、信用账本、SaaS 草稿订单。
- **已真实接通**：无 Phase 4 商业化能力。
- **等待外部权限**：微信/支付主体、在线收款、发票、电子签、短信、生产模型价格和商家试点账号。
- **不可用**：真实收款、自动开通、正式开票、自动续费、佣金结算和生产收入确认。

## 强制财务边界

`SaaS Billing` 的付款方是商家，收款主体是梧曜科技；`Consumer Commerce` 的付款方是消费者，收款对象是相应商家或合法支付主体。两者不得共享订单号、退款、发票、收入科目、余额流水或数据库表。当前 `src/domain/billing.js` 与 `src/domain/commerce.js` 保持独立，后续数据库必须增加外键、权限和对账边界。

## 外部阻塞

- 生产数据库、消息队列、密钥管理、监控和备份环境未提供。
- SaaS 收款主体、微信支付商户/服务商资质、发票和电子签账号未提供。
- 商家准入资料、合同模板、税务口径、退款政策和试点商家名单未提供。
