# 商品、知识库与直播配置联调

## 本地启动

在 `backend/growth-api` 运行：

```bash
bash scripts/init-local.sh
docker compose up -d
docker compose wait minio-init
bash scripts/mvn-local.sh spring-boot:run
```

在仓库根目录运行 `npm run dev`。前端默认 `http://localhost:4173`，
API 为 `http://localhost:18080`，MinIO 为 `http://localhost:39000`。
根目录 `VITE_DEV_API_TARGET` 可覆盖开发代理目标；修改后需重启 Vite。
本地短信默认使用控制台发送器，验证码在后端日志中查看，不会发送真实短信。

## 接入范围

- 顶部门店选择：读取当前登录账号可访问的门店；「＋」新建门店，编辑按钮修改名称、地址、电话和营业时间。
- `/assets/products`：商品增删改查、实物/卡券分类、多张商品图、商品 FAQ。图片预签名上传到对象存储，数据库仅保存素材 ID 和顺序。
- `/knowledge`：FAQ 知识集和问答管理、启用、发布、停用、归档。文档上传/解析尚未开放。
- `/digital-human`：场次草稿、商品选择及顺序、话术风格、节奏、互动问答等配置保存与恢复。直播中手动新增商品会实际创建到商品库。

商品、知识集、场次使用真实门店 ID；租户只从登录令牌获取。
浏览器仅缓存当前账号选中的门店 ID，服务器返回的权限列表决定该选择是否仍有效。
已接入模块不使用演示商品或 localStorage 作为业务数据库。

## 问答来源与保存

直播选中的商品自动带入其有效 FAQ。门店通用问答来自 `PUBLISHED` 知识集中的
`ACTIVE` 条目。启动知识快照的优先级为 `SESSION > PRODUCT > STORE`；
文字未命中的问题交给文案模型，见[弹幕回复](live-browser-audio-integration.md#弹幕回复)。

添加每条问答时，默认关联「本场通用」、保存「仅本场」。可选择：

| 保存位置 | 行为 |
| --- | --- |
| 仅本场 | 保存为场次问答，可关联本场已选商品 |
| 本场 + 关联商品问答 | 保留本场问答，并新增商品 FAQ |
| 本场 + 门店知识库草稿 | 保留本场问答，并新增目标 FAQ 集中的草稿，需到知识库启用 |

已保存问答的卡片内编辑和删除只影响本场副本；已沉淀到商品库或知识库的内容单独维护。
商品编辑、直播草稿和本场问答带版本校验；商品 FAQ 或图片独立变更也会递增父商品版本，
避免旧编辑窗口覆盖直播新沉淀的内容。版本冲突时保留表单并显示错误。

## 当前边界

保存直播配置可用；本轮已增加真实浏览器配对/WebSocket心跳、Web Audio音频队列、三种接法记录、人工收音测试、门店授权声音样本与可替换 CosyVoice API 适配器。网页不再使用 SpeechSynthesis 或 mock 连接冒充服务。
供应商账号未配置，真实 TTS/克隆与对录硬件效果尚未实测。模拟弹幕由文案模型先判断是提问、想买、需要人工处理还是无需回复，再依据问答和商品资料用口语回答（2026-10-05 加入；判断提示词用真实模型跑过一轮，整条链路未用真实服务连起来跑过）。真实抖音弹幕、正式计费尚未接通。详见[当前播报实现与边界](live-browser-audio-integration.md)及[语音供应商选型](live-voice-provider-selection.md)。
后端 `/start` 是内部场次状态与知识快照接口，不代表建立了真实直播连接。
